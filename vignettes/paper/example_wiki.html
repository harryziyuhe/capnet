Web Traffic Model Example

Harry He

2026-07-26

Purpose of vignette

This vignette illustrates capnet in a domain other than finance: forecasting daily aggregate Wikipedia traffic from a panel of individual, heavy-tailed article-level pageview series. Article popularity on the web is famously Zipf/heavy-tailed – a small number of articles can go “viral” and receive orders of magnitude more traffic than usual on a given day. A linear (here, Poisson) forecasting model that regresses tomorrow’s site-wide traffic on today’s per-article pageviews is exactly the setting capnet targets: without a contribution cap, a single freak spike in one article’s traffic can swamp the forecast, even though the underlying coefficient is not unusually large under a standard elastic-net fit.

Data

The dataset (inst/extdata/wiki_traffic.csv) contains daily English Wikipedia pageviews (2022-01-01 to 2024-12-31) for 30 widely-read articles (major tech companies, AI/crypto topics, and prominent public figures), pulled from the public Wikimedia Pageviews REST API. The response is next-day total pageviews summed across all 30 articles; the covariates are today’s per-article pageviews (in thousands of views, for numerical scaling). The total column is dropped from the covariate set since it is an exact linear combination of the 30 article columns.

wiki <- read.csv(system.file("extdata", "wiki_traffic.csv", package = "capnet"))
wiki$date <- as.Date(wiki$date)

articles <- setdiff(names(wiki), c("date", "total"))

wiki <- wiki |>
  arrange(date) |>
  mutate(target = dplyr::lead(total, 1)) |>
  filter(!is.na(target)) |>
  mutate(across(all_of(articles), ~ . / 1000)) |>   # thousands of views
  select(date, target, all_of(articles))

The summary statistics show pronounced positive excess kurtosis for several articles (e.g. sam_altman, elon_musk, nvidia), confirming that a handful of articles experience occasional traffic spikes far outside their typical range – precisely the covariate behavior contribution caps are designed to control.

Backtest

We forecast next-day total pageviews with a Poisson log-link model, using a rolling one-year training window refit monthly (steps of 5 days within each month, to keep runtime moderate) and evaluated out-of-sample from 2023-01-01 through 2024-12-31. Refit months are independent of one another, so rolling_enet() dispatches them across CPU cores via parallel = TRUE. Because Poisson deviance scales with the (very large) raw pageview counts, we set alpha = 0 and forgo elastic-net selection entirely (lambda = 0) so that the comparison isolates the effect of the contribution cap alone, exactly mirroring the role gamma plays in the finance example.

Contribution ceilings are computed the same way as in the finance vignette: as a multiple of each feature’s univariate regression coefficient with the response, here using a univariate Poisson GLM slope (the natural analogue of the OLS slope used for the Gaussian model) rather than the raw correlation.

wiki_L <- function(train_use, target_col, feature_cols, y_train) {
  sapply(feature_cols, function(v) {
    uni <- suppressWarnings(
      stats::glm(train_use[[target_col]] ~ train_use[[v]], family = "poisson")
    )
    3 * abs(stats::coef(uni)[2])
  })
}

results <- rolling_enet(
  wiki,
  date_col = "date",
  target_col = "target",
  alpha = 0,
  window_years = 1,
  method = c("capnet_walk", "capnet", "postcap"),
  capnet_gamma = c(0),
  walk_gamma = c(10, 100, 1000, 10000, 100000),
  min_obs = 200,
  eval_start = "2023-01-01",
  family = "poisson",
  cap_formula = wiki_L,
  lambda_override = 0,
  walk = 5,
  parallel = TRUE
)

combos <- results$predictions %>%
  dplyr::distinct(method, gamma) %>%
  dplyr::arrange(method, gamma)

predictions <- list()
contributions <- list()
methods <- c()
gamma_vals <- c()

for (i in seq_len(nrow(combos))) {
  m <- combos$method[i]
  gamma_j <- combos$gamma[i]

  predictions[[i]] <- results$predictions %>%
    dplyr::filter(method == m, gamma == gamma_j)
  contributions[[i]] <- results$contributions %>%
    dplyr::filter(method == m, gamma == gamma_j)
  methods[i] <- m
  gamma_vals[i] <- gamma_j
}

The uncapped Poisson model is catastrophically unstable out-of-sample: with 30 correlated daily-traffic covariates and no regularization, it occasionally produces an enormous predicted count when a covariate combination lands far outside the training distribution, driving its out-of-sample pseudo-R^2 deeply negative. Post-fit capping clips the worst contributions after the fact but does not let the coefficients adjust, so it remains unstable (pseudo-R^2 still negative). The walk-forward capnet model, which incorporates the contribution cap directly into estimation, is dramatically more stable across the entire range of gamma values tested and is the only approach with a positive out-of-sample pseudo-R^2.

The maximum-contribution series shows the mechanism behind the stability difference: the uncapped model occasionally lets a single article’s lagged pageviews swing the log-mean forecast by several units (a multiplicative factor of \(e^{|\cdot|}\) on the predicted count – catastrophic for a Poisson mean), while the walk-forward capnet model keeps this quantity close to the cap throughout, redistributing predictive weight across the panel instead of concentrating it in one article.

Contribution redistribution snapshot

2023-03-14 is the single day responsible for the uncapped model’s worst out-of-sample blowup: a spike in youtube’s lagged pageviews (relative to that fit’s training distribution) pushes its uncapped log-mean contribution far above any other feature, producing an implausible next-day forecast.
